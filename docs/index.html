How it works

From Jinja template to paper, in one hop.

The service reads what your ERPNext print format already renders. No new templating language, no field mapping UI — your receipt HTML goes in, printer bytes come out.

Features

Built for real POS counters.

Everything a production receipt pipeline needs — nothing it doesn't.

4–10× faster printing

Receipts print in 0.5–1s — no print dialog, no rendering wait. The service streams raw ESC/POS straight to the spooler.

Truly cross-platform

Native installers for Linux (.run), Windows (.exe) and macOS — self-contained, no Python required on the target machine.

Localhost-only by design

Listens exclusively on 127.0.0.1:5058. The receipt never leaves the machine — no cloud relay, no telemetry, no attack surface.

Fully localized receipts

Literal mode transcribes exactly what your Jinja renders — tax tables, amount-in-words and fiscal layouts flow through untouched.

Graceful fallback

If the service is down, POSAwesome falls back to the browser print dialog automatically. Printing never becomes a single point of failure.

Control panel & self-update

Built-in web panel at localhost:5058 — set the default printer, view logs, fire test prints. Releases update the service on their own.

Cash drawer control

One call to /api/cash-drawer pops the register drawer via the printer port. Test prints included for setup days.

58mm & 80mm paper

Per-request paper_width. The API-print marker comment in your print format (58MM/80MM) routes the receipt automatically.

Tested, versioned, observable

Full pytest suite, /health endpoint exposing the running version, and CI-built installers attached to every GitHub release.

Print modes

Two modes. You author the receipt, the service prints it.

No language detection, no country configuration. Which mode you get is decided by one attribute on your print format — and legacy installs keep working unchanged.

Recommended

Literal mode

data-print-mode="literal"

Your print format owns the entire layout. The service transcribes exactly the lines your Jinja renders — nothing added, nothing dropped.

  • Fiscal layouts, tax tables & amount-in-words pass through as-is
  • Alignment, bold & double-size via simple CSS classes
  • Tables → left/center/right column lines
  • Blank guarded sections never leave empty lines
  • Right choice for any localized or country-specific ticket
<div data-print-mode="literal"> … </div>

Modeled mode

default fallback

The service recognizes a standard receipt shape and lays it out for you — ideal for simple, uniform tickets.

  • Detects company, items, taxes, total, payments & change
  • Multilingual anchors — Total:, Totaal:, Factura:…
  • Printed labels keep the receipt's own language
  • Extra sections via data-print="header|fiscal|footer" blocks
  • Keeps pre-literal installs working unchanged
works with no attribute at all

API

A REST surface you can curl from anywhere.

Five endpoints, JSON in and out. POSAwesome ships the client — but anything that can POST HTML can print.

POST /api/print-html
curl -X POST http://localhost:5058/api/print-html \
  -H "Content-Type: application/json" \
  -d '{"printer":"ThermalPrinter",
      "html":"<html>...</html>",
      "paper_width":58}'
POST /api/cash-drawer
curl -X POST http://localhost:5058/api/cash-drawer \
  -d '{"printer":"ThermalPrinter"}'
GET /health & /api/printers
curl http://localhost:5058/health
# → version, uptime — probe auto-updates

curl http://localhost:5058/api/printers
# → enumerate system printers
POST /api/test-print
curl -X POST http://localhost:5058/api/test-print \
  -d '{"printer":"ThermalPrinter",
      "paper_width":58}'

Install

Up and printing in minutes.

Prebuilt, self-contained installers from CI — or run from source if you prefer.

1

Download the installer

Grab the .run (Linux) or .exe (Windows) from the GitHub Releases page. Fully self-contained — no Python on the target machine.

2

Create the ERPNext Print Format

Sales Invoice · Custom Format · start the HTML with the API-print marker, then paste the literal 80mm example (or 58MM for narrow paper).

3

Set it on the POS Profile

Assign the Print Format to your POS Profile. POSAwesome sees the marker and routes receipts to localhost:5058.

4

Open the control panel

Visit http://localhost:5058/ to pick your default printer, review the log and fire a test print.
